# Что запускать дальше — сценарии Sattva

Главный вопрос в работе с цепочкой скиллов — «что я делаю сейчас и что дальше». В Sattva ответ всегда в трёх местах:

1. **Последняя строка ответа** каждого скилла: `Next: <команда с путями>` или `Next: ничего — ждём <событие>; потом <команда>`.
2. **Серая подсказка в пустом поле ввода** после хода Sattva — та же команда с путём к плану, Tab или → вставляет её.
3. **`/sattva-status`** в любой момент: активный план, его статус, задачи, гейты, стоимость и строка `Next:`. Без вызова модели.
   Те же команды стоят кнопками над полем ввода (клик вставляет команду, Enter жмёте вы); пути к файлам в ответах
   кликабельны; при разросшемся контексте `/sattva-handoff` передаёт задачу в чистую сессию через план. Вернулись больше чем
   через час (кэш остыл) — полоса предложит **«Начать чисто»**: `/clear` без вызова модели и следующая команда плана в
   поле ввода, вся история не перечитывается по полной цене.

Если ни одно из трёх не помогло — найдите свою ситуацию ниже.

## Где я сейчас (по статусу плана)

| Что видно | Где вы | Следующая команда |
|---|---|---|
| Активного плана нет | ничего не начато | `/sattva:start <задача своими словами>` |
| `intent.md` есть, `Status` не `accepted` | intent ждёт вашей подписи | прочитать intent и `/sattva:intent accept <путь>` |
| intent принят, плана нет | можно планировать | `/sattva:plan <путь к intent.md>` |
| План `Status: draft` | план ждёт Approve; код закрыт гейтом | прочитать план и ответить Approve в `/sattva:plan <путь к plan.md>` |
| План `approved` | можно реализовывать | `/clear`, затем `/sattva:implement <путь к plan.md>` (на Sonnet) |
| План `implementing`, есть `- [ ]` | реализация не закончена | `/sattva:implement <путь к plan.md>` — продолжит с первой открытой задачи |
| План `implementing`, все задачи `[x]` или `BLOCKED` | можно проверять | `/clear`, затем `/sattva:verify <путь к plan.md>` |
| verify: **PASS**, в плане есть открытый `## Release` | можно выпускать | `/sattva:implement <путь к plan.md>` — режим релиза: каждый merge / push / деплой после вашего «да» |
| verify: **PASS**, без `## Release` | готово | push и PR (на L сначала `/sattva:review`) |
| verify: **PASS-UNPROVEN** | часть строк не доказана | запустить недостающую проверку или `/sattva:verify accept <путь>` с вашей подписью |
| verify: **FAIL** | есть `missing` / `wrong`, Rules gate `fail` | `/sattva:fix verify` (все находки за один проход) или `/sattva:implement <путь>` для недоделанной задачи |
| План `verified` или `abandoned` | задача закрыта | следующая задача: `/sattva:start …` |

## Сценарии

### Новая фича с решениями (уровень L)
`/sattva:start <фича>` → он скажет L → `/sattva:intent <идея>` (внутри grill задаёт вопросы, вы отвечаете) →
`/sattva:intent accept <путь>` → `/sattva:plan <путь к intent>` (сам запускает check) → Approve → `/clear` →
`/sattva:implement <план>` → `/clear` → `/sattva:verify <план>` → на L `/sattva:review` → push и PR.

### Понятная задача на несколько файлов (M)
`/sattva:start` → M → `/sattva:plan <задача>` → Approve → `/sattva:implement` → `/sattva:verify` → push.

### Горят сроки
`/sattva:start --rush <задача>` → M: `/sattva:plan <задача> --rush`, L: `/sattva:intent --rush <идея>` →
`/sattva:intent accept <путь>` → `/sattva:plan <путь к intent>` → вопросы одним пакетом → Approve → цепочка идёт
сама до вердикта. Остановилась (`Rush остановлен на …`) → `/sattva:implement <план>` продолжает с того же места.
Выключить — убрать `Pace: rush` из шапки плана. Подробно — [Режим rush](../README.ru.md#режим-rush).

### Мелкая правка (S)
`/sattva:start <правка>` → S → агент правит и проверяет сразу, без плана. Отчёт `Level: S`. Всё.

### Баг
`/sattva:fix <описание или текст ошибки>` → выбрать «исправить сразу» (S) или «сначала план» (M) → для M:
Approve → `/sattva:implement` → `/sattva:verify`. Регрессионный тест пишется новым файлом, старые тесты закрыты гейтом.

### Сделал только grill — что дальше?
grill сам ничего не сохраняет: решения D1…Dn живут в чате. Запишите их:
`/sattva:intent <тема> — решения D1…Dn выше` (L) или `/sattva:start <тема> — D1…Dn выше`, если уровень неясен.
Решили подождать (например, внешнего события) — так и пишите: `Next: ничего — ждём <событие>`; когда событие
произойдёт, `/sattva:start <тема>` и ссылка на заметку с решениями.

### Вернулся после перерыва
`/sattva-status` → строка `Next:`. Или откройте `docs/sattva/` и найдите самую новую папку: её `plan.md` и есть
активная задача, статус — в его шапке.

### Ждём внешнего события (деплой, правило WAF, ответ коллеги)
Sattva ничего не запускает. Задача остаётся в своём статусе; когда событие случится — `/sattva-status` подскажет,
откуда продолжить.

### Главная сессия запустила дочерние
Когда дочерняя сессия заканчивает ход, приложение сообщает об этом главной, и Sattva сам разбирает семью (`/sattva:sessions`; вручную — в любой момент): готовые архивируются, недоделанной простаивающей уходит одно сообщение со следующим шагом, остальные — в списке «ждут тебя» с причиной. В CLI тот же разбор показывается по worktree, только для чтения.

### Вторая сессия на том же плане
Второй `/sattva:implement` (или `/sattva:fix`) останавливается до первой правки: «План <папка> ведёт <место> · ветка …». Ответьте `Стоп` и запустите позже или `Забрать план`, если первой сессии уже нет (после 2 ч без отметки это рекомендованный ответ); первая остановится перед следующей задачей. Без сети или origin защита действует только между worktree этой машины.

### Новый проект или проект без CLAUDE.md
`/sattva:setup` (контекст, правила, MCP) → по желанию `/sattva:architecture`, `/sattva:docs`,
`/sattva:dockerize`, `/sattva:ci` → дальше обычные задачи через `/sattva:start`.

### Перед деплоем / после изменений auth, платежей, ввода
`/sattva:security <путь к плану или папка>` → `Security gate: pass | warn | fail`. На L verify требует его сам.

### Проверить вручную или агентом
`/sattva:qa <план>` (сценарии) → `/sattva:qa-check human` или `/sattva:qa-check agent`.

### Одни и те же ошибки повторяются
`/sattva:evolve` → правила в `.claude/rules/` после вашего «да». Из другого проекта — `/sattva:transfer <путь>`.

### Нужен факт, а не мнение
`/sattva:ask <вопрос>` — ответ только на доказательствах, иначе «не хватает данных: …».

### Проект начинали с AI Factory
Sattva не читает `.ai-factory/*`: планы оттуда для него не активные, гейты их не видят. Новые задачи начинайте с
`/sattva:start`, а не с `/aif-plan`; решения из старого плана передайте своими словами:
`/sattva:intent <тема> — решения: …`.
