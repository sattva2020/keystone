# Что запускать дальше — сценарии Keystone

Главный вопрос в работе с цепочкой скиллов — «что я делаю сейчас и что дальше». В Keystone ответ всегда в трёх местах:

1. **Последняя строка ответа** каждого скилла: `Next: <команда с путями>` или `Next: ничего — ждём <событие>; потом <команда>`.
2. **Серая подсказка в пустом поле ввода** после хода Keystone — та же команда с путём к плану, Tab или → вставляет её.
3. **`/keystone-status`** в любой момент: активный план, его статус, задачи, гейты, стоимость и строка `Next:`. Без вызова модели.
   Те же команды стоят кнопками над полем ввода (клик вставляет команду, Enter жмёте вы); пути к файлам в ответах
   кликабельны; при разросшемся контексте `/keystone-handoff` передаёт задачу в чистую сессию через план. Вернулись больше чем
   через час (кэш остыл) — полоса предложит **«Начать чисто»**: `/clear` без вызова модели и следующая команда плана в
   поле ввода, вся история не перечитывается по полной цене.

Если ни одно из трёх не помогло — найдите свою ситуацию ниже.

## Где я сейчас (по статусу плана)

| Что видно | Где вы | Следующая команда |
|---|---|---|
| Активного плана нет | ничего не начато | `/keystone:start <задача своими словами>` |
| `intent.md` есть, `Status` не `accepted` | intent ждёт вашей подписи | прочитать intent и `/keystone:intent accept <путь>` |
| intent принят, плана нет | можно планировать | `/keystone:plan <путь к intent.md>` |
| План `Status: draft` | план ждёт Approve; код закрыт гейтом | прочитать план и ответить Approve в `/keystone:plan <путь к plan.md>` |
| План `approved` | можно реализовывать | `/clear`, затем `/keystone:implement <путь к plan.md>` (на Sonnet) |
| План `implementing`, есть `- [ ]` | реализация не закончена | `/keystone:implement <путь к plan.md>` — продолжит с первой открытой задачи |
| План `implementing`, все задачи `[x]` или `BLOCKED` | можно проверять | `/clear`, затем `/keystone:verify <путь к plan.md>` |
| verify: **PASS**, в плане есть открытый `## Release` | можно выпускать | `/keystone:implement <путь к plan.md>` — режим релиза: каждый merge / push / деплой после вашего «да» |
| verify: **PASS**, без `## Release` | готово | push и PR (на L сначала `/keystone:review`) |
| verify: **PASS-UNPROVEN** | часть строк не доказана | запустить недостающую проверку или `/keystone:verify accept <путь>` с вашей подписью |
| verify: **FAIL** | есть `missing` / `wrong`, Rules gate `fail` | `/keystone:fix verify` (все находки за один проход) или `/keystone:implement <путь>` для недоделанной задачи |
| План `verified` или `abandoned` | задача закрыта | следующая задача: `/keystone:start …` |

## Сценарии

### Новая фича с решениями (уровень L)
`/keystone:start <фича>` → он скажет L → `/keystone:intent <идея>` (внутри grill задаёт вопросы, вы отвечаете) →
`/keystone:intent accept <путь>` → `/keystone:plan <путь к intent>` (сам запускает check) → Approve → `/clear` →
`/keystone:implement <план>` → `/clear` → `/keystone:verify <план>` → на L `/keystone:review` → push и PR.

### Понятная задача на несколько файлов (M)
`/keystone:start` → M → `/keystone:plan <задача>` → Approve → `/keystone:implement` → `/keystone:verify` → push.

### Мелкая правка (S)
`/keystone:start <правка>` → S → агент правит и проверяет сразу, без плана. Отчёт `Level: S`. Всё.

### Баг
`/keystone:fix <описание или текст ошибки>` → выбрать «исправить сразу» (S) или «сначала план» (M) → для M:
Approve → `/keystone:implement` → `/keystone:verify`. Регрессионный тест пишется новым файлом, старые тесты закрыты гейтом.

### Сделал только grill — что дальше?
grill сам ничего не сохраняет: решения D1…Dn живут в чате. Запишите их:
`/keystone:intent <тема> — решения D1…Dn выше` (L) или `/keystone:start <тема> — D1…Dn выше`, если уровень неясен.
Решили подождать (например, внешнего события) — так и пишите: `Next: ничего — ждём <событие>`; когда событие
произойдёт, `/keystone:start <тема>` и ссылка на заметку с решениями.

### Вернулся после перерыва
`/keystone-status` → строка `Next:`. Или откройте `docs/keystone/` и найдите самую новую папку: её `plan.md` и есть
активная задача, статус — в его шапке.

### Ждём внешнего события (деплой, правило WAF, ответ коллеги)
Keystone ничего не запускает. Задача остаётся в своём статусе; когда событие случится — `/keystone-status` подскажет,
откуда продолжить.

### Новый проект или проект без CLAUDE.md
`/keystone:setup` (контекст, правила, MCP) → по желанию `/keystone:architecture`, `/keystone:docs`,
`/keystone:dockerize`, `/keystone:ci` → дальше обычные задачи через `/keystone:start`.

### Перед деплоем / после изменений auth, платежей, ввода
`/keystone:security <путь к плану или папка>` → `Security gate: pass | warn | fail`. На L verify требует его сам.

### Проверить вручную или агентом
`/keystone:qa <план>` (сценарии) → `/keystone:qa-check human` или `/keystone:qa-check agent`.

### Одни и те же ошибки повторяются
`/keystone:evolve` → правила в `.claude/rules/` после вашего «да». Из другого проекта — `/keystone:transfer <путь>`.

### Нужен факт, а не мнение
`/keystone:ask <вопрос>` — ответ только на доказательствах, иначе «не хватает данных: …».

### Проект начинали с AI Factory
Keystone читает `.ai-factory/*` как запасной источник: планы из `.ai-factory/plans/` находит `check`, решения D1…
из плана считаются intent. Новые задачи начинайте с `/keystone:start`, а не с `/aif-plan`.
