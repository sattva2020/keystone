## What it shows

- On all three seeded gaps the plain baseline caught the gap as well as Keystone: 15/15 for every arm. On these
  tasks `/keystone:verify` adds no catches over Opus asked plainly, and costs about 3.8× as much and takes about 4.8×
  as long.
- Keystone's lower total comes entirely from `clean`: it returned FAIL in 4/5 runs, the other arms in 1/5 each. Every
  one of those FAILs, in all arms, names the same two points: `truncate(s, n)` returns more than `n` characters when
  `n ≤ 0`, and `slugify` drops non-ASCII letters. The first is a real defect in the "clean" seed, so `clean` is not
  clean and its expected PASS is questionable; Keystone flags that edge case more consistently, not a phantom.
- It cannot show more than that: four tiny repositories, 5 runs per cell, and the bootstrap intervals cover only
  run-to-run noise, not task choice. The keystone arm's prompt also differs (it runs the command), so the arms differ
  in more than the plugin.

## After the run (2026-10-18)

The verify of the benchmark plan found that the `clean` seed was not clean: its `truncate(s, n)` returned more than
`n` characters for `n <= 0`. The seed is fixed (`truncate(s, 0) == ""`, with a unit test and a hidden check), so the
`clean` rows above come from the old, defective seed and need a rerun. The weak-test evidence pattern was tightened to
`assertIsNotNone|\btest_total_rounds\b`; `--rescore` of this run gives the same table.
